# 0.4.0 — CLI integration, standby mode, UI overhaul

## The bar

The toolbar buttons used Unicode glyphs (`◉`, `◇`, `≡`, `✕`). Those characters are
not in the default Windows UI font, so they fell back to whatever font had them —
or to a bare dot. That is why several buttons looked like unlabelled dots.

They are now stroked vector geometries in `src/CPT.Shell/Icons.xaml`, drawn on a
24×24 grid and rendered through two styles in `Theme.xaml`
(`ToolbarIconButton` for actions, `ToolbarIconToggle` for state). Geometry has no
font to fall back from, so the icons look identical on every machine, and an "on"
toggle is now an unmistakable filled accent tile rather than a slightly different
dot.

The bar also gained a status strip showing which coding CLI is linked, with a
colour-coded dot. Clicking it opens setup.

## Per-turn CLI settings

Model, thinking effort and permission level are now selectable, driven by the
same data as everything else: each provider declares `Options` — a list of
labelled choices and the arguments each one contributes — and the Agent tab
builds its pickers from whatever the selected CLI actually supports. The
argument template says where they land, via an `{options}` placeholder, because
Claude takes its prompt after `-p` while Codex takes it last.

The flags were read from the installed CLIs rather than assumed:

| CLI | Model | Effort | Permissions |
| --- | --- | --- | --- |
| Claude Code | `--model` | `--effort low…max` | `--permission-mode` |
| Codex CLI | `-m` | `-c model_reasoning_effort` | `--sandbox` |
| Gemini CLI | `--model` | — | `--approval-mode` |
| Copilot CLI | `--model` | — | `--allow-all-tools` |

Every option's default contributes no arguments, so a fresh install behaves
exactly like running the CLI by hand, and an unknown stored choice falls back to
that default rather than producing an invalid command line. Both are pinned by
tests.

## UI chrome

The bar's hamburger menu is gone; a single settings button opens the settings
window, which now holds everything in five tabs — Agent, Standby, Personas,
Speech, Advanced. The tray menu is down to four entries.

The white patches were WPF's stock templates showing through. `ComboBox`,
`CheckBox`, `RadioButton`, `ContextMenu`, menu separators and `ToolTip` had
theme *setters* but no template, so their popups, check glyphs, radio dots and
separators were still drawn in system light chrome. All six are now fully
retemplated. Tooltips in particular were unreadable; they are now dark, rounded
and offset off the cursor.

Toolbar controls also carry `AutomationProperties.Name`, and the combo box
template names its popup `PART_Popup`, without which the control is invisible to
screen readers.

## One window

The app was spawning a window per screen: settings opened a persona editor, which
opened a clip picker, which sat on top of a cloning-setup dialog. Everything now
lives in the settings window.

- `Views/SettingsPage.cs` — the base class for what used to be dialogs. A pane
  reports `Finished`, can update its own title, and can ask the shell to push
  another pane on top of it.
- `SettingsWindow` keeps a stack of panes over the tabs, with one Back button.
  CLI setup, the persona editor, the clip picker, cloning setup and the voice
  test are all panes now.
- The persona manager window is gone; its list, edit, export, import and delete
  all live on the Personas tab.
- Confirmations happen where the action is rather than in a dialog: Delete
  becomes "Really delete?" until clicked again, and a too-short voice sample
  turns the button into "Use it anyway". Only the file pickers and the crash
  report remain as separate windows, and both are the operating system's.

## Dark title bars

`DarkTitleBar` sets DWMWA_USE_IMMERSIVE_DARK_MODE on every window through a
class handler registered once at startup. A WPF caption is drawn by the desktop
window manager, not by WPF, so no amount of styling reaches it — a dark app
otherwise wears a white title bar.

## Voice cloning from a YouTube video

Persona editor → **Pick from video…** opens a picker: paste a link, watch the
video, and mark the stretches where only the voice you want is speaking. Only
those stretches are cut out and joined into the cloning sample.

A video is almost never usable whole — there is an intro, a second speaker, a
laugh track — which is why marking exists rather than just taking the first 45
seconds, as the old YouTube import did.

- `Media/VoiceClip.cs` — clips are normalised before use: sorted, clamped to the
  video, merged where they overlap or nearly touch, and dropped when a double-tap
  produced nothing. Marking happens by ear against a moving playhead, so the raw
  set is never clean.
- `Media/AudioClipper.cs` — one ffmpeg pass with an atrim/concat filter graph,
  rather than a process per clip and a concat file. Each fragment gets
  `asetpts=PTS-STARTPTS`; without it concat keeps the original offsets and pads
  the gaps with silence.
- `Media/YoutubeAudio.cs` — reads id, title and duration, then downloads the full
  audio track as 16 kHz mono while the user is still watching.
- `Controls/ClipTimeline.xaml` — the tag strip: marked regions, the mark in
  progress, a playhead, a minute grid and click-to-seek.
- `CPT.PlayerWeb/index.html` — the video pane. WebView2 cannot see into a
  cross-origin YouTube iframe, so the page uses the IFrame API and forwards the
  playhead to the host, which is what the timeline and the mark button run on.

### The strip is draggable, and never was clickable

Dragging empty track scrubs the video; dragging a marked section's edge trims it;
dragging its middle slides it whole, keeping its length. A press inside a section
without movement still seeks, because the marked parts are where you most want to
jump to. `Media/TimelineMath.cs` holds the arithmetic — where a time sits, what a
pixel means, what a press grabs — apart from the control, so 21 tests cover the
behaviour without needing a window.

Building it exposed that the strip had never received a single mouse event, so
even click-to-seek had never worked. The cause: input was handled on a `Canvas`,
and a Canvas only hit-tests where it has actually drawn — `Background="Transparent"`
on it does not create a click surface the way it does on other panels, and the
shapes it holds are cleared and rebuilt on every redraw. Input now goes to an
explicit `Rectangle Fill="Transparent"` laid over the canvas.

Verified on a real video: dragging a clip's middle moved 0:08–0:15 to 0:12–0:19
with its length intact, and dragging its start edge pulled 0:12 back to 0:09 with
the end held.

The hovered time is also drawn on the strip now instead of shown in a tooltip:
WPF puts a tooltip under the pointer, where it would intercept the next press.

### The marked sections teach the persona twice

The clipped audio is the cloned voice, and — with "Also learn how they talk from
this clip" ticked — it is also transcribed, and those phrases go to the front of
the persona's writing samples. That matters because the alternative source is the
whole video's captions, which contain every other speaker in it; the marked
sections are the one place we know only the target speaker is talking.

`PersonaBuilder` used to transcribe the sample only when there were no text
samples at all, and nothing in the UI ever set the flag that enabled it, so the
path was dead. It now merges rather than substitutes, and reports progress.

### Speech recognition was silently deaf

Transcribing the clip surfaced a defect that predates all of this:
`WhisperCpp` passed `-otxt -of -`, which makes whisper-cli write the transcript
to a file and print nothing. Every call returned an empty string, so push-to-talk
and standby heard nothing and said nothing about it. Dropping those two flags —
whisper-cli prints to stdout on its own — fixed it: 71 characters in 933 ms from
a ten-second clip. A test now asserts the flags stay gone.

Two more defects found by testing it rather than reasoning about it:

- `PostWebMessageAsJson` delivers an already-parsed object to the page, not a
  string, so the page's `JSON.parse` threw and every command was silently
  dropped. The page now accepts either.
- WebView2 refuses to start playback without a click inside the page, and the
  Play button is outside it. All WebView2 environments now come from
  `WebViewEnvironment`, which sets `--autoplay-policy=no-user-gesture-required` —
  shared because every environment on one user-data folder must be created with
  identical options.

The WebView2 also hosts its own window, which paints over WPF content regardless
of z-order, so the "video unavailable" message is shown by collapsing the view
rather than layering over it.

## Coding CLI integration

CPT now drives one of four CLIs and sets it up itself:

| CLI | Vendor | npm package |
| --- | --- | --- |
| Claude Code | Anthropic | `@anthropic-ai/claude-code` |
| Gemini CLI | Google | `@google/gemini-cli` |
| Codex CLI | OpenAI | `@openai/codex` |
| GitHub Copilot CLI | GitHub | `@github/copilot` |

The user's only job is signing in.

### How it is put together

- `Cli/CliProvider.cs` — an immutable, JSON-serialisable description of a CLI:
  how to install it, how to prompt it, how to detect and obtain auth.
- `Cli/CliProviderCatalog.cs` — the four built-in definitions. Any of them can be
  replaced at runtime by dropping `<id>.json` into
  `%LOCALAPPDATA%\CustomPersonaTranslator\cli-providers`, so a renamed flag can be
  repaired without a new build.
- `Cli/ExecutableResolver.cs` — resolves a command the way a shell would. This
  matters: with `UseShellExecute=false`, Windows only ever appends `.exe`, and all
  four CLIs install as npm `.cmd` shims, so a bare `claude` would never launch.
  Batch shims are routed through `cmd.exe /d /c`.
- `Cli/ProcessLauncher.cs` — `ProcessRun`, a child process whose output is read
  line by line, killed with its tree if abandoned. Arguments go through
  `ArgumentList`, never a joined command line.
- `Cli/Streaming/` — one small, pure reader per output shape, decoding into
  provider-neutral `CliTurnEvent`s. Being pure line-in/events-out is what makes
  them testable against captured transcripts.
- `Cli/CliAgent.cs` — one conversation. Turns are serialised, because these CLIs
  keep conversation state in a file that two concurrent processes would corrupt.
- `Cli/CliOrchestrator.cs` — the only thing the rest of the app talks to.

### Why turns use pipes and sign-in uses a pseudo-console

Conversation turns run through each CLI's non-interactive prompt mode with
redirected pipes. Driving the interactive TUI instead would mean parsing a screen
redraw. But every one of these CLIs refuses its interactive login when it cannot
see a terminal, so sign-in runs in a real Windows pseudo-console
(`Pty/PtySession.cs`) that CPT hosts itself — which is also what lets the setup
window show the flow inline and notice the moment it succeeds, by polling for the
credential file the CLI writes.

## Standby mode

Say the wake phrase, dictate, say the send phrase. All three phrases (wake, send,
cancel) are user-configurable, along with the silence timeout, maximum request
length and microphone sensitivity.

- `Voice/PhraseMatcher.cs` — matches on normalised word sequences, not
  substrings. "Hey, Agent!" matches; "agentic" does not.
- `Voice/VoiceActivityDetector.cs` — hysteresis in both directions. Speech must
  stay loud briefly to start and quiet noticeably longer to end. The asymmetry is
  deliberate: a false start costs one wasted transcription, a false end truncates
  what the user was saying.
- `Voice/StandbyStateMachine.cs` — the conversation rules, with no audio or timers
  attached, so they are fully testable.
- `Voice/StandbyListener.cs` — the runtime: continuous capture, a pre-roll buffer
  so the first syllable of the wake phrase is not clipped, and a single background
  worker for transcription because the engine is a subprocess.

Only complete utterances are transcribed, so the machine is idle between
sentences instead of running speech recognition on a silent room.

## Project-wide quality pass

`Directory.Build.props` now turns on `latest-recommended` analysers with
`TreatWarningsAsErrors` for every project. That surfaced, and this change fixes,
a set of real defects in existing code:

- `LlamaCppClient`, `PersonaResearchAgent`, `PiperVoiceDownloader` and
  `TranslationPipeline` owned disposables without being disposable.
- Locale-sensitive `StartsWith`/`EndsWith`/`int.Parse` on protocol data
  (SSE frames, VTT captions, model filenames) — these would misbehave under a
  Turkish locale.
- Cancellation tokens dropped at several `await` sites.
- `JsonSerializerOptions` reallocated per call in the persona hot path.
- A leaked temporary WAV in `PersonaBuilder`.

`AppSettings` also gained atomic saves (temp file plus move) and a round-trip
check that rewrites `settings.json` whenever the build knows about options the
file does not, so the file on disk always describes what is available.

## Tests

`tests/CPT.Tests` (xunit, 76 tests) covers phrase matching, the standby state
machine, voice-activity detection, all four CLI output readers, argument
building, command-line quoting and transcript clean-up. `tests/CPT.Smoke` keeps
its role as a manual integration harness, and gained an `agent` command that runs
one real turn against the configured CLI.

## Verified on this machine

- Claude Code 2.1.220 — detected, linked, one real turn in 3.0 s.
- Codex CLI 0.151.0 — detected, linked, one real turn in 6.1 s.

Testing against the real `codex exec --json` found a defect the synthetic tests
had missed: the shipped build labels its payload `type`, not `item_type`. The
reader now accepts both, and a test built from the captured output pins it.
