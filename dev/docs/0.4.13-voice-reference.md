# 0.4.13 ? Preserve chosen clone reference

The C-3PO clip session contained four selected clips totaling 50.69 seconds. The app persisted the correct combined source, but clone_server.py replaced it with a pitch-selected nine-second middle slice. This discarded most of the selected speech before the speaker encoder ran. The installed Chatterbox prepare_conditionals implementation already limits its own acoustic and token prompts to ten/six seconds while building the speaker embedding from the full reference.

The wrapper now passes the original reference intact to prepare_conditionals and caches conditionals by path, size and modification time. It does not modify or delete source audio. Existing short derived WAVs are left untouched but no longer used. Cached acknowledgement keys are versioned to avoid replaying audio generated by the old reference logic.

The Delivery slider's Expressiveness property was also omitted from the JSON synthesis command. It is now captured per request and sent as exaggeration, including queued requests. The protocol check exercises different values across a canceled request and its successor. Python regression checks cover full-reference forwarding, caching, changed-file invalidation and missing references.

These fixes address reference selection and parameter plumbing; successful PCM generation does not establish perceptual voice similarity.
