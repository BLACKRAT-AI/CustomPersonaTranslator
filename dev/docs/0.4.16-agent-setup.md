# 0.4.16: consistent computer-agent setup

New-agent creation used only the global provider and left options empty. Provider switching also cleared options. Old visible-chat connections remained text-only, and live changes could leave the current conversation using old tool configuration.

AgentSetup is now shared by creation, loading, provider changes and activation. Existing Codex profiles are repaired once using a persisted SetupVersion: legacy visible-chat routing becomes background Codex, with desktop tools and filesystem/network access. Missing model/effort/speed choices receive desktop-assistant defaults. Explicit custom event links and other providers are preserved. After this migration, deliberate changes such as disabling desktop access or choosing visible chat survive reloads.

New agents inherit the current provider, persona, model choices and working folder, with their own option dictionaries. Codex agents get desktop access and fast mode without manual configuration. Every request reapplies live agent settings. Changes to tools, permissions or extensions reset only the affected conversation; switching agents retains separate contexts and ordinary model changes do not discard them. Selecting a provider also clears stale extra tool arguments.

Validation: 341 unit tests passed, including new-agent defaults, legacy migration, deliberate post-migration choices, independent option ownership and conversation reset/isolation. UI smoke checks passed. Actual desktop verification uses AppServices and the shared agent factory, without injected options or MCP arguments. Early runs demonstrated existing/new-agent screen control, but also exposed one missing audio-level observation and one unavailable test-window screenshot; those failures are retained rather than counted as end-to-end successes.

The repeated existing -> new -> existing sequence completed all three screen tasks using the real desktop. Diagnostic PCM logging isolated the missing audio to an engine result of only 0.20 seconds of near-silence. The server now rejects empty/silent or implausibly short speech and retries the same selected reference once. A second unusable result is an explicit failure, with no preset substitution. Four Python checks cover validation and the actual server JSON retry/success/failure flow using a fake model. The UI harness now gates its final-answer audio check on the final speech phase, excluding acknowledgement audio. None of these checks establish clone likeness.
