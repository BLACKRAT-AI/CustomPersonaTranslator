# 0.4.4 status

The conversation is now part of the projector panel, with a shared border. Collapse hides history and the composer, retains messages, and saves the preference. Response messages have a Repeat message button on hover or keyboard focus; replay uses the stored answer and persona without a CLI rewrite or rerunning actions.

Codex Fast mode is selectable independently in agent and persona rewrite settings. It sets service_tier="fast" and features.fast_mode=true. Supported models consume more credits. This is a speed option, not a guarantee of request completion or total latency.

An opt-in local stdio desktop MCP tool is included in the EXE. It offers screenshots, mouse movement/clicks, text, key chords and scrolling. Only the answering Codex agent receives it; text rewriting does not. It has no network listener and ends with the CLI process tree. It does not bypass Windows elevation or CLI policy.

## Verification

325 unit tests passed. UI smoke verified all panes, message scrolling, response-only replay buttons appearing on hover, and collapse/expand retaining history.

The first desktop test failed because non-interactive Codex denied MCP requests under approval_policy="never". Desktop sessions now route requests through on-request plus auto_review, including resumed turns. This uses the supported approval reviewer, which may still deny an action; it does not bypass safety checks.

Live desktop test passed: the agent read a random code from a screenshot, clicked the field, typed the exact code, clicked Verify, and inspected VERIFIED. The test checks the window's actual contents and click event rather than the assistant's claim. Separate tool calls took 40.4 seconds. A screenshot followed by one reviewed click/type/click batch took 30.3 seconds. These are individual observations, not latency guarantees. No Outlook task was retried.

Run CPT.UiSmoke.exe --verify-desktop to open the disposable visible target and run the test. The published EXE's stdio MCP initialization and tool discovery also passed.

## Remaining latency

This is still a CLI-per-request pipeline, not a persistent realtime voice system. Fast mode does not eliminate transcription, process startup, model/tool round trips, approval review, or speech synthesis latency. Thirty seconds for a small desktop task is still slow. Persistent agent sessions and streaming speech are the next architectural work, not capabilities delivered by this release.
