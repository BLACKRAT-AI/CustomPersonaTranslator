# 0.4.3 — Request execution and response latency

The app now displays each request and complete answer independently of speech,
with live activity, elapsed time, a text input, Stop, and New conversation. The
conversation stays available when the hologram fades or a voice engine fails.

## Execution

- Codex and Claude resume the session ID reported by their own process. They
  no longer select whichever conversation happened to run most recently.
- Conversations are separated by agent, provider, and working directory.
  Switching between Computer and Jarvis preserves each agent's own context.
- Provider selection is synchronous. A late readiness probe cannot overwrite a
  different provider's status, and a request can initiate the readiness check.
- Each agent's Keep context setting is honored. Busy requests are reported
  explicitly instead of silently queued for later execution.
- Failed Codex turns report the error even if earlier progress text said that
  work was about to start. Tool activity is surfaced without synthesizing it.
- The request prompt explicitly scopes persona rewriting to the final report
  and requires tool evidence before claiming an action succeeded.

## Audio and responsiveness

- Agent output is consumed without awaiting narration synthesis or playback.
- The answer is displayed as soon as it is available. Acknowledgements are
  cancelled when the answer arrives.
- Voice installation checks use Python module discovery rather than importing
  Torch and Chatterbox into an extra, disposable process on the UI thread.
- Cold cloned voices load in the background; that reply uses the preset voice.
  A slow synthesis has a 12-second budget before falling back for that reply.
- Cancelling clone synthesis returns immediately. The pipe exchange still owns
  and drains its response, so the next request cannot receive stale audio.
- Speech operations share an exclusive player; cancellation releases it before
  the next operation. Shutdown cancels work and disposes the clone process.
- Microphone transcription failures and empty recordings have visible feedback.
  Holding the microphone captures the mouse, so releasing outside it still stops
  recording. Typing no longer triggers the single-letter toolbar shortcuts.

## Verification

`dotnet test` covers 320 cases, including new session isolation, provider switching,
error decoding, duplicate event, and speech cancellation regressions. The UI smoke
harness builds every window and pane without starting background inference.

`verify-agent` used the configured Codex/Astra agent to create a file, start a
separate conversation with a different remembered value, resume the first, and
update its file with the original value. The file contents were checked on disk.
Measured turns: 15.1 s, 6.1 s, and 13.4 s. These are observations from this machine,
not a guarantee of service latency.

`verify-voice` cancelled an in-flight test synthesis in 159 ms, then verified that
the next synthesis received its own complete PCM data. `--verify-turn` exercises
the real app service, CLI, and audio output; it requires a configured voice engine.
The final live check returned the answer in 7.5 s and completed audible preset
playback in 11.8 s with a cold cloning engine.

CLI session handling follows the installed CLI help and the official
[non-interactive mode documentation](https://learn.chatgpt.com/docs/non-interactive-mode).
